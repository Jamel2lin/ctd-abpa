# 项目背景

开发面向企业内部ERP、OA、HR等异构老旧系统的跨系统表格数据自动化桥接与处理智能体，支持自然语言指令驱动，可自动完成多源异构表格解析与字段语义对齐、跨表复杂业务逻辑计算筛选、异常数据隔离处理，输出符合目标系统导入标准的表格文件，保障数据计算精准、格式兼容与运行鲁棒性，并支持自定义匹配规则适配新增报表场景。

# 跨系统表格数据自动化桥接与处理智能体

## 一、项目任务概述

开发一款针对企业内部异构老旧系统（如 ERP、OA、HR 系统）的数据自动化桥接智能体。

由于部分老旧系统接口封闭或不支持 API 直连，业务人员高度依赖人工导出、筛选、计算及重组电子表格，以完成不同业务系统之间的数据流转。

本项目要求构建智能体应用，通过理解用户的自然语言指令，自动化完成多源表格的解析、复杂业务逻辑的筛选计算以及目标格式的转换与输出。

具体业务数据及数据说明后续提供。

## 二、业务数据流向

### 2.1 源系统导出端

获取来自企业内部不同业务系统的原始结构化表格，包括但不限于：

- ERP 系统导出的加班记录等业务数据；
- OA 系统导出的请假单等审批数据；
- HR 系统导出的年假余额等人事数据；
- 其他老旧业务系统导出的 Excel、CSV 等结构化数据。

### 2.2 智能体处理中枢

智能体作为不同业务系统之间的数据处理中枢，主要完成以下任务：

#### 2.2.1 意图与表头解析

理解用户自然语言指令，对不同来源表格的字段、表头及数据含义进行语义解析，并完成异构字段之间的自动对齐。

#### 2.2.2 复杂逻辑与筛选计算

根据预设或用户指定的业务规则，对多个表格执行关联、筛选、判断、计算及数据转换等操作。

#### 2.2.3 字段重组与格式转换

完成多源数据聚合、字段重组、数据清洗以及格式标准化，将处理结果转换为目标系统要求的数据结构。

### 2.3 目标系统导入端

根据目标老旧系统的导入规范，自动生成完全符合其要求的标准导入模板，使生成结果能够直接用于目标系统的数据导入。

## 三、核心业务需求

### 3.1 异构表格解析与字段映射

系统应具备跨表语义理解与字段自动对齐能力。

针对不同源系统导出的表格在表头命名、日期格式、人员标识等方面存在的差异，智能体需要：

- 自动解析不同表格的结构及字段含义；
- 自动识别不同表格中的关联键，如工号、姓名等；
- 建立不同来源字段之间的映射关系；
- 根据目标系统的导入规范，将源字段映射至目标模板指定列；
- 对日期、数字、文本、人员标识等字段进行必要的格式标准化。

### 3.2 复杂业务逻辑运算与高级筛选

系统不应仅执行简单的数据复制与粘贴，而应具备复杂跨表业务逻辑计算能力。

#### 3.2.1 假期余量结算示例

系统读取员工请假单并获取总休假天数，同时关联员工年假余额表。

系统按照业务规则执行以下逻辑：

1. 获取员工总休假天数；
2. 获取员工当前可用年假余额；
3. 优先使用年假额度抵扣休假天数；
4. 当休假天数超过年假余额时，将超出部分自动转换为事假天数；
5. 在最终输出表中分别记录年假天数与事假天数；
6. 确保最终计算结果与人工使用电子表格公式计算的结果完全一致。

#### 3.2.2 动态筛选

系统支持根据用户指定的业务条件，对全量数据进行精准过滤。

筛选条件包括但不限于：

- 指定部门；
- 指定员工；
- 指定时间段；
- 指定业务类型；
- 指定审批状态；
- 多条件组合筛选。

### 3.3 异常数据处理与兜底机制

针对老旧系统导出数据中可能存在的格式残缺、空值、异常字符或类型不匹配等问题，系统需要具备完善的容错机制。

系统应满足：

- 单条异常数据不得导致整体任务失败；
- 自动识别空值、异常字符、类型错误及格式异常；
- 对无法完成字段映射的数据进行隔离；
- 对存在业务逻辑冲突的数据进行标记；
- 正常数据继续完成处理和输出；
- 对异常数据生成独立的异常处理日志；
- 日志应提供足够的信息供业务人员进行人工复核。

## 四、泛化与自适应能力

系统应具备一定程度的泛化能力，以适应企业业务系统和表格结构后续发生的变化。

当出现初期测试用例中不存在的新型报表或未知字段结构时，系统应支持通过以下方式进行适配：

### 4.1 自动语义匹配

利用字段名称、数据内容及上下文信息，对未知字段进行语义分析，并尝试建立与标准字段之间的映射关系。

### 4.2 交互式规则指定

当系统无法可靠判断字段含义或映射关系时，应允许用户通过自然语言对话指定匹配规则。

### 4.3 配置化规则管理

系统可提供配置界面或配置文件，使用户能够维护：

- 字段映射规则；
- 数据类型转换规则；
- 跨表关联规则；
- 业务计算规则；
- 数据筛选规则；
- 输出模板规则。

通过规则配置机制，应对未来不断变化的业务表格结构。

## 五、技术声明

### 5.1 底层技术选项

开发团队可根据实际业务场景自主选择：

- 大语言模型及相关框架；
- Agent / 智能体框架；
- 自动化工具链；
- Excel / CSV 数据处理库；
- 数据校验框架；
- 数据库及缓存方案；
- 前后端开发技术栈。

系统架构及具体技术实现方式原则上不作限制。

### 5.2 交付导向

项目以实际业务可用性和最终交付结果为核心。

系统必须重点保障：

1. **数据处理准确性**  
   数值计算、字段转换和业务逻辑判定必须具备确定性，尤其是涉及业务数值计算的场景，不允许由大模型直接生成未经验证的计算结果。

2. **数据真实性**  
   数据处理过程中不得出现内容捏造、字段虚构或数据失真。

3. **格式兼容性**  
   最终生成的电子表格必须严格符合目标老旧系统的导入规范。

4. **业务可落地性**  
   最终输出结果应能够直接服务于目标系统的数据导入流程，而非仅作为数据分析或展示结果。

## 六、验收要求

### 6.1 逻辑计算精度验收

抽取包含复杂跨表计算逻辑的实际业务场景进行测试，例如：

- 年假余额抵扣；
- 事假自动转换；
- 跨表数据关联；
- 多条件业务筛选。

系统计算并生成的最终表格数据，应与人工使用电子表格公式计算的结果**完全一致**。

### 6.2 格式兼容度验收

系统生成的最终电子表格文件应能够直接上传至目标老旧系统。

例如，将生成的 HR 加班数据导入目标 HR 系统加班模块时：

- 不出现字段缺失；
- 不出现字段类型错误；
- 不出现日期或数字格式错误；
- 不出现模板结构错误；
- 不触发目标系统格式校验报错；
- 数据能够正常完成导入。

### 6.3 抗错鲁棒性验收

在源表格中人为注入异常数据，包括但不限于：

- 干扰字符；
- 空行；
- 空值；
- 非法日期；
- 数值类型异常；
- 字段缺失；
- 格式不一致。

系统在上述情况下：

1. 不发生程序崩溃或整体任务中断；
2. 正常数据能够继续完成处理；
3. 异常数据能够被准确识别和隔离；
4. 最终能够正常生成目标结果表格；
5. 同时生成对应的异常标记及异常处理日志。
