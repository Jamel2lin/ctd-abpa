# 业务规则

## 异常分级与处置总则

| 等级 | 定义 | 默认动作 | 自动化边界 |
| --- | --- | --- | --- |
| L1 | 自动标准化 | 自动清洗并保留原值、来源和转换记录 | 可自动处理；无法确定时升级 L3/L4 |
| L2 | 确定性业务异常 | 已有适用且已发布规则时确定性计算，否则暂停并提示 | 仅允许执行已确认规则 |
| L3 | 数据冲突 | 暂停受影响记录并隔离，人工复核 | 禁止智能体自动裁决 |
| L4 | 系统级未知 | LLM 分析并提出建议 | 人工确认、权限校验、版本化并发布后才能修改规则库 |

系统不得让 LLM 猜测冲突数据。按以下 System of Record / Source of Truth 处理：

| 数据域 | 权威系统 |
| --- | --- |
| 员工身份、姓名、入离职日期 | HR Master Data |
| 请假审批结果 | OA |
| 实际打卡 | 考勤系统 |
| 加班业务记录 | ERP |

同一记录内不同字段可分别服从各自权威来源。例如 ERP 加班记录中的工时以 ERP 为准，姓名和工号关系仍以 HR Master Data 为准。

## ERP 加班转 HR

输出列固定为“工号、姓名、部门、职位、起始日期、申请加班”。筛选边界包含起止值。

- 负工时：按 L3 固定采用异常提醒方式。暂停并隔离该条记录，提示人工核实；禁止智能体自动修正、冲销、归零或发布自动处置规则。
- 零工时：按 L2 保留并警告；审批状态和企业规则可确定时再自动决定是否进入计算。
- 同一工号对应多个姓名：按 L3 固定采用异常提醒方式。该工号全部记录隔离并提示人工复核；禁止智能体自动关联、自动更名或选择其中一个姓名，必须依据 HR Master Data、有效期和工号复用情况核实。
- 异常超长工时、加班重叠、加班与请假重叠：按 L3 暂停相关记录，不自动截断或抵消。

## OA 请假转 HR

请假小时按“天 × 8 + 小时”换算为整数分钟后写回小时文本。起止日期和时间按本地时间拼接，不做时区转换。输出工作表固定为“导入HR 格式”，所有单元格为文本。

## 年假优先抵扣

默认只抵扣事假。按工号精确关联并核对姓名、部门；按开始时间、单据编号、源行号依次扣减。部分抵扣输出相邻的年假与事假两行。余额缺失、重复、非法或身份冲突时隔离请假单。旧余额必须显式确认。余额仅标注年月且请假发生在同月时，因无法确定余额截至日，也必须显式确认；标注完整日期时按日比较。

网页/API 的旧余额确认必须同时具有显式布尔同意、非空人工签署人和核实依据；未勾选、缺签署/依据或字符串 `"true"` 均不得通过。审批保留余额时点、参与结算的最新日期、原因、签署时间与实际操作身份。来源、规则、模板、表头或补丁变化后须重新预演和确认。CLI 保留既有显式 `--allow-stale-balance` 兼容入口，不具备网页审批会话；正式业务签署应使用网页/API 记录。

## 人工核验记录与未完成的主数据对接

2026-10-03 起，固定业务和通用任务的修正/排除补丁必须记录处理原因、核实依据、来源文件哈希与稳定行列位置，并在运行中保存快照。依据应引用原单或 HR 主数据日期及记录编号，身份冲突应同时说明有效期和工号复用核验结果。原文件不直接改写，原异常与历史运行可追溯。

目前核实依据为人工填写文本，系统未自动接入权威 HR 主数据，也未验证所填依据的真实性。主数据系统、快照时间、有效期重叠处置、离职再入职与工号复用政策须由业务方提供并签认，随后实现时点化校验。已有合成关联测试只能证明关联与隔离机制，不能证明来源权威性。
