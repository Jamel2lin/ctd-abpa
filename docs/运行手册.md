# v0.2.0 本地运行与验收手册

## 启动与检查

使用 Node 24、pnpm 11，在项目根目录运行 `pnpm install`、`pnpm dev`。网页默认 `http://127.0.0.1:3211`，API 默认 `http://127.0.0.1:3210`。首次启动可用 `pnpm lint && pnpm typecheck && pnpm test && pnpm build && pnpm test:e2e` 检查部署。数据保存在本机 `.tasks/`，版本化网页规则保存在 `.config/`；备份任务时两者应一并保存。

## 固定业务任务

在网页新建任务、上传导出文件并分析结构。核对文件、工作表和行数后输入指令，生成计划。本地预览应检查输出行数、异常和年假扣减口径。仅在确认余额时点及本次范围后确认计划，再执行并下载 HR 文件、异常日志、对账与 ZIP。修改来源或计划后必须重新预览、确认。若源文件内容在确认后变化，执行返回 409 并撤销确认；恢复原文件或点击“重新分析已有文件”，再预演、确认。重新分析会归档与新哈希不符的旧补丁，历史运行目录仍保留。

CLI 示例与配置格式见 `README.md` 和 `配置说明.md`。通用 V2 须先从工作簿分析结果获取 artifact/sheet/column ID，再准备已发布规则、模板和计划 JSON。可通过 `pnpm bridge run-v2`，或在网页“规则与模板版本”发布配置，再于“V2 通用任务”绑定、预览、确认、执行。网页另有 DeepSeek V2 计划建议入口；它只接收结构信息，实际模型联调与新场景对话验收尚未完成。

## 模型与隐私

DeepSeek 需在部署环境中设置 `DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL`，并按 `.env.example` 配置 provider、URL 与超时。切勿把密钥写入规则、任务对话或验收记录。模型只接收脱敏结构；未配置模型时可执行已确认规则，未知指令应停留在澄清状态。OpenAI、Gemini、Qwen 在本版不承担真实联调门槛。

## 文件交付前

运行 `pnpm demo && pnpm verify:artifacts`，核对文件签名、工作表、表头、类型、行数、异常及 SHA-256。通用模板超过 `maxDataRows` 或 `.xls` 行容量时自动分批；经典 HR 导出仍按现有 BIFF8 容量拒绝超限输入。如具备真实 HR 环境，导入后填写 `验收/真实HR导入记录模板.md`；赛事未提供环境时，使用 `验收/真实HR导入记录-2026-09-17.md` 的替代验收，并明确披露未验证真实系统隐藏约束。
