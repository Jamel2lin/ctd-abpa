# v0.2.0 本地运行与验收手册

更新日期：2026-10-03。当前整改状态见[整改报告](问题整改与剩余问题报告-2026-10-03.md)，证据入口见[验收索引](验收/验收索引.md)。

## 启动与检查

使用 Node 24、pnpm 11，在项目根目录运行 `pnpm install`、`pnpm dev`。网页默认 `http://127.0.0.1:3211`，API 默认 `http://127.0.0.1:3210`。首次启动可用 `pnpm lint && pnpm typecheck && pnpm test && pnpm build && pnpm test:e2e` 检查部署。数据保存在本机 `.tasks/`，版本化网页规则保存在 `.config/`；备份任务时两者应一并保存，包括任务数据库、源文件、运行目录及 `access-audit.jsonl`。

## 登录与任务权限

默认回环单人运行使用 `local-user` 管理员身份。共享或经反向代理开放时必须配置 `API_USERS`、实际网页的 `CORS_ORIGINS` 和 `API_ALLOWED_HOSTS`；直接外部监听且未配置用户时拒绝启动。即使代理后端仍监听回环，也必须主动启用认证。配置方法见[配置说明](配置说明.md)。网页用个人令牌登录，再选择已授权任务；API 可使用 `Authorization: Bearer <个人令牌>`。

管理员可管理共享配置和任务授权；操作员可创建、运行自己或获编辑授权的任务；只读用户可查看和下载获授权任务。共享映射修改需要管理员。任务授权目前通过管理员调用 `PUT /api/tasks/:id/access` 完成。令牌由部署方发放，登录会话有效期八小时，服务重启后需重新登录。HTTPS 部署设置 `AUTH_COOKIE_SECURE=true`。

## 固定业务任务

在网页新建任务、上传导出文件并分析结构。核对文件、工作表和行数；识别有误时展开“工作表与表头纠错”，查看前 100 行，选择工作表并输入表头行号（多行用英文逗号分隔），然后应用。应用后须重新生成或绑定计划。自动识别对前 100 行评分；若这些行全空则暂选后续首个非空行，避免阻断上传纠错。识别仍属启发式，复杂或更长前言需人工指定；当前原始行预览仅覆盖前 100 行。

输入指令并生成计划。本地预览应检查输出行数、异常和年假扣减口径。旧余额或仅标月份且无法证明覆盖请假日期时，预览披露余额时点、最新参与结算日期及原因；必须单独勾选、填写核实签署人和依据，才能确认。明确截至日覆盖请假日期时无需旧余额确认。该签署记录表达人工核实结果，系统不会替代 HR 的真实性判断。

确认后执行并下载 HR 文件、异常日志、对账与 ZIP。修改来源、表头、补丁或计划后必须重新预览、确认。若源文件内容在确认后变化，执行返回 409 并撤销确认；恢复原文件或点击“重新分析已有文件”，再预演、确认。重新分析会归档与新哈希不符的旧补丁，历史运行目录仍保留。

## 通用表单配置与异常重跑

切换“通用表格任务”，展开表单编辑器，核对输入工作表和逻辑字段。可添加映射、类型转换、复合键关联与身份核验、类型化计算、条件筛选，以及汇总和排序；配置输出格式、工作表名、列顺序、类型、必填、长度、默认值和容量。点击“校验并保存表单配置”，复核修订差异后“确认并发布表单规则”，再“绑定表单计划”。接下来完整预演、确认、执行和下载。已有发布规则和模板可从列表选择复用；编辑未保存时禁止绑定。高级算子及多工作表输出仍使用 JSON/CLI，表单校验不替代业务核对。

固定业务与通用 V2/V3 异常均可点击“修正源值并预览”或“排除源行并预览”；修正时选择实际源列、新值，并填写人工处理原因和核实依据。身份冲突应填写 HR 主数据的日期及记录编号。源文件保持原样，补丁绑定输入哈希和稳定来源 ID，重新预演后必须重新确认。每次运行保存补丁快照和审批记录，旧运行产物仍可下载。异常列表支持分页，不再只显示前 20 条。

CLI 示例与配置格式见 [README](../README.md) 和[配置说明](配置说明.md)。模型建议只接收受控结构上下文；2026-09-15 的硅基流动指定模型验收是历史证据，本次未复测真实模型，官方 DeepSeek 直连与真实连续对话仍待专项验收。

## 容量与故障处理

上传按流写入，默认每个文件最多 100 MiB、每次最多五个文件。超限返回 413，失败上传会清理本次临时文件。执行仍为单机串行，`MAX_PENDING_RUNS` 默认 10，计入已接收且未完成的执行请求；过载返回 429 和 `Retry-After: 5`，任务原确认保留，可稍后重试。管理员可通过 `GET /api/metrics` 查看队列、进程内存、事件循环利用率和限制。

运行 `pnpm benchmark:capacity` 可复现合成 CSV 转换、100 分类汇总、XLSX 写出与复读基准。现有 1 万/10 万行结果见[容量记录](验收/容量基准-2026-10-03.json)，不代表大 XLSX 或并发用户的容量上限。解析和执行仍会使用内存，应按部署数据另行压测。

## 模型与隐私

DeepSeek 需在部署环境中设置 `DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL`，并按 `.env.example` 配置 provider、URL 与超时。切勿把密钥写入规则、任务对话或验收记录。模型只接收脱敏结构；未配置模型时可执行已确认规则，未知指令应停留在澄清状态。OpenAI、Gemini、Qwen 在本版不承担真实联调门槛。

## 文件交付前

运行 `pnpm demo && pnpm verify:artifacts`，核对文件签名、工作表、表头、类型、行数、异常及 SHA-256。通用模板超过 `maxDataRows` 或 `.xls` 行容量时自动分批；经典 HR 导出仍按现有 BIFF8 容量拒绝超限输入。如具备真实 HR 环境，导入后填写 `验收/真实HR导入记录模板.md`；赛事未提供环境时，使用 `验收/真实HR导入记录-2026-09-17.md` 的替代验收，并明确披露未验证真实系统隐藏约束。
