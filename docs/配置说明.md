# 配置说明

配置位于 `profiles/`，通过 `id` 与 `version` 标识。配置可保存源工作表、表头指纹、字段映射、关联键、过滤器、业务规则及目标模板。生产环境修改配置时应提升版本号，保留旧版本以复现审计结果。

字段匹配优先级为标准字段名、内置别名、用户配置、模型建议。若一个标准字段出现多个候选列，系统拒绝自动选择并要求确认。

## V2 规则与模板

V2 计划必须固定 `rules.id/version` 和 `targetTemplate.id/version`。执行服务只接受状态为 `published` 且步骤与计划完全一致的规则版本；草稿、错版或执行后被修改的输入均拒绝执行。

规则只能包含 `ProcessStepV2` 白名单算子，计算只能使用类型化表达式 AST。模板配置位于 `templates/`，控制格式、工作表、表头行、列顺序、必填、类型、数字格式、默认值、长度和容量。

无模型执行示例：

```bash
pnpm bridge inspect data/input.xlsx
pnpm bridge run-v2 --plan plan.json --rules rules.json --template template.json --input data/input.xlsx --output outputs/result.xlsx
```

计划中的 `artifactId`、`sheetId` 和列索引来自 `inspect` 结果；不得写入任意文件路径。

## 模型配置

默认 provider 为 `deepseek`。必须显式配置 `DEEPSEEK_MODEL` 和密钥引用指向的环境变量后才显示可用；模型 ID 会写入任务对话的调用记录。DeepSeek 使用 Chat Completions JSON Output，并在本地再次执行 Zod 业务校验。参考 [DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode/)。

OpenAI 适配入口使用 Responses API 的 Structured Outputs，并固定 `store:false`，本版默认 `OPENAI_ENABLED=false`。参考 [OpenAI Responses API](https://developers.openai.com/api/reference/cli/resources/responses/methods/create)。DeepSeek 官方、硅基流动、Gemini 和 Qwen 分别使用 `.env` 中独立的密钥、模型和服务地址；API 请求可通过 `provider` 选择 `deepseek`、`siliconflow`、`gemini` 或 `qwen`。硅基流动渠道对 `deepseek-ai/DeepSeek-V4-Flash` 使用官方推荐的 `json_schema` Structured Outputs，固定 `enable_thinking:false` 和 `temperature:0`，并检查实际模型及 `finish_reason`；非递归语义动作由本地编译为完整 Rule IR。参考[硅基流动 Chat Completions](https://docs.siliconflow.cn/docs/api/chat-completions-post)。Gemini 调用 [generateContent JSON 接口](https://ai.google.dev/api/generate-content)，Qwen 调用[百炼兼容 Chat 接口](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions)。

认证错误不重试；超时、限流和服务错误最多重试两次。密钥值不会由模型状态 API 返回，也不会写入任务对话或请求正文。

真实模型验收命令：`pnpm test:model:real -- --output=docs/验收/真实模型验收.json`。默认执行五类能力、每类五种表达、每种三轮；`MODEL_VALIDATION_CONCURRENCY` 可控制并发。
